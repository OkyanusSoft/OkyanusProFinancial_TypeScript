## ✨ الفكرة الجوهرية: نظام واحد — كل الأنشطة

بدلاً من شراء نظام للمطعم وآخر للمستشفى وثالث للمصنع… **النظام المالي المتكامل** يحمل محركاً تكيفياً يغيّر هيكلة البيانات والمصطلحات والقوائم ونمط نقاط البيع **تلقائياً** حسب النشاط الذي يفعّله صاحب النظام من شاشة واحدة محمية برقم سري.

- 🏪 **سوبر ماركت؟** → نقاط بيع بالباركود والسلة ومصطلحات «صنف/عميل/فاتورة».
- 🍽️ **مطعم؟** → نقاط بيع بالطاولات والطلبات ومصطلحات «طبق/زبون/طلب».
- 🏥 **مستشفى؟** → حجوزات مرضى وغرف وعمليات، وذمم تحليلية لكل مريض **دون تضخيم دليل الحسابات**.
- 🏭 **مصنع؟** → أوامر إنتاج وخطوط ومستلزمات، تُرحَّل قيمها للحسابات العامة بقيد متوازن.

> فعّل النظام الذي طلبه عميلك ← تتشكل القائمة الرئيسية ← تتكيف المصطلحات ← تُهيأ البيانات ← يعمل النظام.

## 🧠 قاعدة البيانات التكيفية (Adaptive Schema)

الوحدات المتخصصة **لا تحتاج جداول جديدة لكل نشاط**:

```
activity_modules  (21 نظاماً — اسم، أيقونة، نمط POS، حساب الإيراد)
      │ 1..n
activity_entities (الوحدات: حجوزات، عمليات، عقود، قاعات…)
      │ 1..n                       ┌─ أعمدة مفهرسة مشتركة (اسم، حالة، مبلغ، تاريخ)
activity_records  ◄────────────────┤
      │ JSON payload               └─ حقول النشاط الخاصة (طاولات، عيارات، عدادات…)
activity_fields   (تعريف الحقول — تُبنى منه الواجهة والتحقق ديناميكياً)
```

إضافة أي عمود أو جدول لأي نشاط مستقبلاً؟ ملف هجرة واحد بأنماط **آمنة للتكرار** (`0005_alter_patterns.sql`).

## ⚖️ الدقة المحاسبية

- **قيد مزدوج صارم**: لا يُرحَّل قيد غير متوازن أبداً (فحص لحظي + محفز قاعدة بيانات).
- **دليل حسابات 5 مستويات** بنمط يمين سوفت التجاري: `1-الأصول` `2-الخصوم` (تشمل حقوق الملكية) `3-المصروفات` `4-الإيرادات` — مع **إضافة حسابات بترقيم تلقائي** حسب آخر رقم في المستوى (`1113 ← 1114`).
- **حسابات تحليلية**: حساب واحد «نزلاء المستشفى» (المستوى 5) يُربط بآلاف الأسماء التحليلية — ذمم دقيقة بلا تضخم في الدليل.
- **إقفال فترات** يرفض أي ترحيل لفترة مقفلة، **عملات متعددة** بأسعار صرف حية، و**مراكز تكلفة** رئيسية/فرعية.
- تقارير IFRS: كشف حساب، ميزان مراجعة، ميزان عمومية، قائمة أرباح وخسائر — **محسوبة فعلياً من القيود** وقابلة للطباعة A4.

## 🔄 المزامنة المركزية اللحظية — حتى 100 مستخدم معاً

```
┌──────────────┐   push (patches + tombstones)   ┌──────────────────┐
│ جهاز الكاشير  │ ─────────────────────────────► │   الخادم المركزي   │
└──────────────┘                                 │  MySQL 8 + WS Hub │
┌──────────────┐ ◄────── بث لحظي فوري ──────────  │  دمج «الأحدث يفوز»│
│ جهاز المحاسب  │                                 └──────────────────┘
└──────────────┘                                          ▲
┌──────────────┐   شاشة مراقبة النشاط (بث حي)             │
│ جهاز المدير   │ ◄──────────────────────────────────────┘
└──────────────┘
```

1. **دمج على مستوى السجل — الأحدث يفوز**: لا يمحُ جهازٌ بياناتَ جهاز آخر **أبداً**.
2. **Tombstones**: الحذف يُنشر بمفتاح فريد — المحذوف يختفي من كل الأجهزة ولا يعود.
3. **رقم الجيل (Gen)**: الاستعادة وإعادة التهيئة ترفع الجيل فتستبدل كل الأجهزة نسخها القديمة تلقائياً.
4. **سجل عمليات متسلسل** للسحب التفاضلي (`pull?since=seq`) للأجهزة المنفصلة.
5. **شاشة مراقبة النشاط** للمدير: بث حي، فلاتر موظف/فئة، توزيع 12 ساعة، أجهزة الشبكة، **واختبار حمل 100 مستخدم**.
